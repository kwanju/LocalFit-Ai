# ADR-034: 캘린더 일정 관리 — ADR-021 스코프 예외 확대 (경량 CRUD)

- **상태**: Accepted (2026-06-17)
- **관련 ADR**: ADR-021 (v4 스코프 — "일과 비서 제외"를 **부분 수정**), ADR-022 (Google Calendar 연동), ADR-002 (단일 사용자)

## 컨텍스트

ADR-021은 v4 스코프에서 **"일과 비서(범용 스케줄 관리)"를 제외**(YAGNI)했고, ADR-022의 캘린더 연동은 **단방향 내보내기 + 틈새 읽기**로 한정했다. 그래서 앱은 운동 일정을 구글 캘린더로 *내보내기*만 하고, 사용자가 **자기 일정을 앱에서 볼 수 없다**.

실사용 피드백(2026-06-17): *"캘린더를 볼 수 있어야 내가 무슨 일정이 있는지 확인하지."* 틈새 추천("저녁 8시까지 비어요")을 신뢰하려면 그 근거인 **일정 자체가 보여야** 한다. 또 운동 일정을 앱 안에서 직접 잡고 싶다는 요구.

PM(아키텍트)이 ADR-021의 제외를 **부분 수정**해, 캘린더 일정의 경량 CRUD를 허용하기로 결정. 단 풀 캘린더 앱(일과 비서)이 되는 것은 여전히 거부 — 운동 코치 맥락의 최소 기능만.

## 결정

ADR-022 연동 위에 **기록 탭 내 경량 캘린더 뷰 + CRUD-lite**를 추가한다.

### 포함 (in scope)
- **보기(read)**: 오늘/이번 주 일정 **목록**(제목 + 시작·종료 시각) + 빈 시간. 단순 리스트(월간 그리드 아님).
- **생성(create)**: 제목 + 날짜 + 시작시각 + 길이(분) 의 단순 일정 1건.
- **삭제(delete)**: 목록의 일정 1건 삭제.
- 기존 "이번 주 운동 등록"(ADR-022)도 이 뷰에서 함께 보임.

### 제외 (여전히 — 일과 비서 방지)
- 일정 **수정(edit)** — P2(삭제+재생성으로 대체). 반복 일정·참석자·알림·위치·첨부.
- 다중 캘린더·캘린더 선택(본인 primary 1개만, ADR-002).
- 월간/주간 그리드·드래그 UI. 타 캘린더 제공자.

### 데이터·프라이버시
- 단일 사용자 본인 primary 캘린더만(ADR-002). 읽은 일정 제목은 **앱 화면 표시용**으로만 쓰고 로컬 외 저장·전송 없음(ADR-022 로컬-only 완화는 캘린더 한정 유지).
- 미연동/오프라인: 캘린더 탭은 "연동 안 됨" 안내 + 코칭은 무영향(degrade).

## 결과

### 긍정
- 사용자가 일정을 보고 틈새 추천을 신뢰. 운동 일정을 앱에서 직접 관리.
- 범위가 "보기+생성+삭제"로 한정 → 풀 캘린더 클라이언트 복잡도(반복·참석자·tz 편집) 회피.

### 부정
- ADR-022 읽기 범위 확대: free/busy(제목 없음) → events.list(제목 포함). 더 민감한 읽기.
- 앱이 캘린더 일부 기능을 떠안음 — 유지보수 표면 증가(ADR-021 YAGNI 정신과 일부 타협).

## 대안
| 후보 | 결정 |
|---|---|
| 읽기 전용 목록만 | 사용자가 생성/삭제도 원함 — 부족 |
| 빈/바쁜 블록만(제목 없이) | "무슨 일정인지" 확인 불가 — 부족 |
| **경량 CRUD(보기/생성/삭제)** | **채택** |
| 풀 캘린더 앱(수정·반복·참석자·그리드) | ADR-021 스코프 과대 — 거부 |

## supersedes
- ADR-021 §"제외: 일과 비서(범용 스케줄 관리)"를 **부분 수정** — 캘린더 경량 CRUD(보기/생성/삭제)에 한해 허용. 영양 추적 등 나머지 제외는 유지.
- ADR-022 §"다른 일정 읽기"의 범위를 free/busy → 일정 목록(제목 포함) 읽기로 확장.
