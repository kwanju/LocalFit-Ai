# ADR-032: 코칭 품질 — 근거 기반 맨몸운동 강도 모델 (RPE/RIR + 점진적 과부하)

- **상태**: Accepted (2026-06-16)
- **관련 ADR**: ADR-013 (능동 코치 — 시스템 프롬프트/액션), ADR-026 (4종 고정), ADR-028 (첫 세션 기준선), ADR-023 (자가보고 컨디션), ADR-002 (단일 사용자·장비 없음)

## 컨텍스트

코칭 정확성이 전적으로 **qwen3.5:9b 의 파라메트릭 지식 + 얇은 프롬프트 규칙**에만 의존한다. 운동 지식 DB·RAG·기준 지침이 없어(grounding 0), 강도·횟수 권고가 출처 없이 환각된다. 실측에서 드러난 실패:

- 사용자가 "스쿼트 50회 가능"이라 **명시**했는데 코치가 임의 보수값(30회/21회)을 고집 — 자가보고를 무시.
- "첫 세트를 제안합니다"라고 **말만 하고** 멈춤(액션 미발행) — 다음 단계 없음.
- "초보자라서" 한 가지 톤(과도한 보수)으로만 응답 — 강도 조절의 기준이 없음.

맨몸운동(홈트, 단일 사용자, 장비 없음 — ADR-002)은 웨이트처럼 **무게를 늘릴 수 없다.** 따라서 강도는 **반복 횟수 · 자극 시간(TUT) · 휴식 · 동작 난이도**로 조절해야 하고, 강도 측정은 **주관적 지표(RPE/RIR)** 가 가장 현실적이다(심박수는 장비 의존이라 후순위). 본 ADR 은 코치가 따라야 할 **기준 지침**을 고정하고, 이를 LLM 에 주입하는 메커니즘을 정한다.

> ADR-026 은 4종 고정의 이유를 "v4 1차 가치는 *같은 4종을 더 똑똑하게 코칭*"이라 적었다. 본 ADR 이 그 "똑똑하게"의 실체다.

## 결정

### §1. 강도 측정 = 주관적 지표 우선 (RPE / RIR)

- **RPE**(자각적 운동 강도, 1~10): 근력·근비대 목표 작업 구간은 **RPE 7~9**("조금 힘들다"~"지치기 직전"). **초보 도입기는 RPE ~7** 로 시작.
- **RIR**(잔여 반복 횟수, "더 할 수 있는데 남긴 수"): 매 세트 **RIR 1~3** 종료가 표준(숙련자에선 실패 1~3회 전 종료가 실패까지 가는 것과 **동등한 근비대 효과** — 검증됨). **초보자는 RIR 2~4**(폼 학습 여유 + 부상 예방, **첫 세션엔 실패 지점 금지**). ⚠️ 초보자는 **실제보다 실패에 가깝다고 오판**하는 경향이 있으므로(연구 확인), 코치는 자가보고를 그대로 믿기보다 여유를 더 두고 폼을 우선시한다.
- 코치는 매 세트 후 자가보고(예: "몇 개 더 할 수 있었어요?")로 RPE/RIR 를 추정해 다음 세트를 **자동 조정(autoregulation)** 한다 — ADR-023 자가보고 정신과 동일.
- **플랭크(등척성)는 RIR 부적용** — RPE + 유지 시간으로 판단하고, **폼이 무너지기 직전 종료**(분 단위 무한 연장 금지).

### §2. 기준선 → 작업세트 (ADR-028 연계, 자가보고 앵커)

- **기준선 = 사용자 자가보고 최대치를 앵커로 삼는다.** 코치는 안전 코멘트만 덧붙이되 **임의로 낮추지 않는다.** 사용자가 명시한 수치/의향이 기본 보수값보다 **항상 우선**(§6).
- **작업세트 = 기준선에서 RIR 만큼 남긴 강도.** 예: 자가보고 최대 50회 → RIR 2~3 을 남겨 한 세트 ~12~15회 × 여러 세트, 또는 사용자가 원하면 더 높게. 첫 세션은 보수적으로 시작하되, **사용자가 더 할 수 있다고 하면 수용**하고 다음 세트에서 올린다.
- **횟수 종목 권장 레인지**: 세트당 **8~15회**가 실패 근처(RIR 1~2)가 되는 난이도. 8~15회가 너무 쉬우면 횟수를 무한정 늘리지 말고 **난이도(템포·가동범위·변형)** 를 올린다.

### §3. 점진적 과부하 (주 단위, autoregulation 우선)

무게 대신 아래 4축으로 매주 조금씩 강도를 올린다. **경직된 "+N" 보다 RPE/RIR 보고에 따른 조정이 우선.**

| 축 | 방법 |
|---|---|
| **볼륨**(세트×반복) | 주 ~5~10% 증가 목표(예: 총 60회 → 65회). 실제 증감은 자가보고 기반 |
| **휴식 단축** | 세트 사이 휴식을 줄여 밀도↑ (예: 90s → 60s) |
| **TUT**(자극 시간) | 템포 큐로 수축·이완 시간↑ (예: 3초 하강 · 1초 정지 · 1초 상승) |
| **동작 난이도**(레버리지) | 지렛대 원리로 같은 종목을 어렵게 (예: 무릎 푸시업 → 일반 → 디클라인) |

- **회복**: 같은 부위 **48시간** 간격, **초보 주 2~3회**. 컨디션 나쁨(ADR-023)이면 볼륨/난이도를 낮춘 제안.
- ⚠️ **레버리지 변형은 "언어 안내"로만**: ADR-026 이 4종(풀업·푸시업·스쿼트·플랭크)을 고정하므로, 변형 동작을 **새 카운팅 종목으로 추가하지 않는다.** 코치가 자세/템포 큐로 *말로* 난이도를 안내하고, 카운팅 엔진은 4종 그대로 추적. (변형의 정식 종목화는 ADR-026 재개 조건 — 후순위.)

### §4. 종목별 적용 (4종 고정)

- **푸시업**(가슴·삼두) / **스쿼트**(하체) / **풀업**(등·이두): 횟수(`reps`) + RIR. **풀업은 난도가 높아** 초보가 0개일 수 있음 → 음성 보조·네거티브(천천히 내리기)를 **언어로 안내**(변형 종목 추가는 안 함).
- **플랭크**(코어, 등척성): **시간(`duration_sec`)** 으로만. RIR 부적용, RPE + 시간 + 폼 기준. (ADR-013 의 "플랭크는 횟수 아닌 초" 규칙 계승.)

### §5. 심박수 — 후순위 (장비 의존)

- 단일 사용자·장비 없음 전제(ADR-002)라 **현재 스코프 밖.** 향후 스마트워치 HR 연동 시에만 의미.
- 참고 공식: 최대 심박수 ≈ **220 − 나이**(거친 근사; Tanaka **208 − 0.7×나이**가 더 정확). 존2~3(60~70%)=지구력/지방연소, 존4(80~90%)=고강도.
- 유산소/HIIT(버피·점핑잭·타바타)는 **현재 4종에 없어 미적용** — 종목 확장(ADR-026) 시 재검토.

### §6. 자가보고 우선 원칙 (회귀 직결)

> **사용자가 명시한 수치·의향은 코치의 기본 보수값을 덮어쓴다. 코치는 자가보고를 기준선 앵커로 삼고, 임의로 낮추지 않는다. 안전 우려는 강요가 아니라 *제안*으로만 표현한다(ADR-013 §수용 정책).**

이 한 줄이 "50회 가능을 무시하고 30회 고집" 버그를 막는 핵심 규칙이다. ADR-013 §수용 정책 + ADR-028 보수적 시작 사이의 충돌을, **자가보고 우선**으로 명시 해소한다.

### §7. 구현 메커니즘 (경량 — RAG 아님)

- 본 지침을 **`ACTIVE_COACH_PROTOCOL`(ADR-013)에 요약 주입** + (선택) 종목 4개의 수치 표를 `app/data/exercise_knowledge.json` 으로 분리해 컨텍스트/프롬프트에 주입. **종목이 4개뿐이라 전량 주입이 검색보다 단순**(풀 RAG·벡터DB 도입 안 함 — YAGNI).
- **단일 LLM 호출 유지**(지연 목표, ADR-013 §4-1). 안전 프리픽스(통증→중단)·한국어 강제는 그대로 최상단.
- 지침은 **소프트 가이드**: 사용자 자가보고/컨디션이 항상 우선하고, 수치는 출발점일 뿐 강제 규칙이 아니다.

## 결과

### 긍정
- 강도·횟수·진행 권고가 **검증된 표준(RPE/RIR/점진적 과부하)** 에 grounding — 환각·무원칙 수치 감소.
- **자가보고 우선**으로 "사용자 무시" 회귀 차단(§6).
- 장비 없는 맨몸운동 현실에 맞는 강도 모델(무게 대신 횟수/시간/휴식/난이도).
- 4종 한정 경량 지식 모듈이라 유지보수 부담 작음.

### 부정
- 프롬프트 토큰 소폭 증가(4종 수치 표·RPE/RIR 규칙). qwen3.5:9b 컨텍스트엔 영향 미미.
- RPE/RIR 자가보고에 의존 — 사용자가 부정확하게 보고하면 강도도 어긋남(autoregulation 으로 점진 보정).
- 레버리지 변형을 언어로만 안내 → 변형 운동의 카운팅 추적은 불가(ADR-026 제약, 의도된 한계).

## 대안

| 후보 | 탈락 사유 |
|---|---|
| 풀 RAG / 벡터 DB 운동 지식 | 종목 4개엔 과설계(YAGNI). 전량 프롬프트 주입이 단순 |
| 코칭 전용 모델 파인튜닝 | 1인 프로젝트 운영·갱신 비용 과다 |
| 심박수 기반 강도(존 2~4) | 장비(스마트워치) 의존 — 단일 사용자 전제 밖, 후순위 |
| 무게/중량 기반 1RM% | 맨몸운동엔 부적용(무게를 못 늘림) |

## 구현 연계 (별도 작업 — 코칭 버그 fix)

본 ADR 의 지침과 별개로, 같은 진단에서 나온 다음 버그는 별도 fix 로 처리한다(ADR 사안 아님):
- **액션–발화 일치 강제**: 코치가 "제안/시작/저장할게요"라 말하면 대응 액션(`propose_set` 등)이 함께 나오게 검증. `set_baseline` 단독 발행 시 `propose_set` 유도 follow-up(plan-adjust follow-up 패턴 재사용).
- **모드 전환 세션 연속성**: 모드 변경(=WS 재연결, `ws.ts`)이 새 세션으로 대화 맥락을 버리지 않게 session_id·이력 인계.
