# Phase v4-8 — 능동 알림 + 백그라운드 스케줄러

## 목적

앱을 켜지 않아도 **운동 시간/체크인을 리마인드**한다(ADR-027). Tauri 트레이에 상주하는 **경량 스케줄러**(모델 없음)가 일정을 읽어 native toast 를 띄우고, **클릭하면 앱 포커스 + 세션 시작 흐름**으로 진입한다. 선제 발화 상시 에이전트가 아니라 **스케줄 기반 리마인드**다(ADR-021/027).

> 탐사에서 toast **표시**(S-6)·트레이 상주(S-7)는 PASS. 이 phase 가 닫는 후속 = **toast 클릭→세션 진입**(S-6 클릭 무반응 발견)과 **스케줄러 로직**.

## 사전 조건

- Phase v4-6(Tauri 셸 — 트레이·notify·세션 진입), v4-4(플랜 = 스케줄 소스) 완료
- 기존 자산: `ui/src-tauri/src/lib.rs`(tray + `notify` command + `show_main_window`), ADR-022 캘린더(phase 9, 미완 — 우선 로컬 스케줄/플랜 소스 사용)

## 관련 ADR

- **ADR-027** — 백그라운드 스케줄러 + native toast + 클릭→세션, 음소거 시간대, 모델 비상주
- ADR-021 — 세션 모델 유지(상시 가동/선제 발화 아님)
- ADR-030 — 스케줄러/트레이는 경량(모델 없음). 알림 클릭→세션 시작 시점에 모델 로드(phase 7)
- ADR-022 — 캘린더(스케줄 소스, phase 9). 미연동 시 로컬 스케줄 fallback

## 작업 항목

### 8-1. 백그라운드 스케줄러 (경량·모델 없음)

- Tauri 트레이에 상주하는 경량 스케줄러가 **운동 일정**(우선 phase 4 주간 플랜의 일자 분배 / 로컬 스케줄. 캘린더는 phase 9)을 읽어 알림 시점 계산.
- **모델 비상주**(ADR-030): 스케줄러는 일정만 읽고 toast 만 발생. 모델은 알림 클릭 후 세션 시작 시점(phase 7)에 로드.
- 구현 위치: Tauri(Rust) 타이머 또는 경량 Python — **모델 없는 경량 프로세스**. 좀비/중복 방지(단일 인스턴스).

### 8-2. Native toast 정책

- 시점: 운동 시간 기준(사용자 설정, 예: N분 전) + 체크인 리마인드.
- **음소거 시간대**(예: 야간) 설정으로 알림 억제.
- 문구: 운동 시간 도래/체크인. `lib.rs` 의 임시 "알림 테스트" 를 정식 알림 경로로 대체.

### 8-3. toast 클릭 → 앱 포커스 + 세션 시작 (★ S-6 후속)

- 탐사 발견: Windows 에서 notification `.show()` 는 **클릭→액션 라우팅을 안 함**(spike-result §S-6).
- 작업: notification action/딥링크 배선 — toast 클릭 → `show_main_window`(이미 lib.rs 존재) + 세션 시작 흐름 진입. Tauri notification plugin 의 action 핸들러 또는 딥링크 스킴.
- 클릭 진입 시 phase 7 모델 로드 + "코치 준비 중" UX 와 자연스럽게 연결.

### 8-4. 안 행복한 경로 (ADR-027)

- OS 알림 꺼짐(집중 모드 등) → 앱 내 **배지/리스트** fallback.
- 스케줄러 프로세스 사망 → 앱 복귀 시 **누락 리마인드 표시**.
- 캘린더 미연동(phase 9 전) → 로컬 스케줄/플랜 기반 알림.
